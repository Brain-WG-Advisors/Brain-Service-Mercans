Purpose of this guide 
This is a technical guide to provide file specification information necessary to create enrollment, return, 
amended return and NACHA files to be submitted to the CT Paid Leave (CTPL) Authority through batch 
processing. 
Important 
Successful file processing depends on files adhering to the strict file specifications as outlined in this guide. 
For information on the process to remit using the CT Paid Leave batch process, read the Batch Contribution 
Process webpage. 
Latest updates 
Updated acknowledgement file information 
When an acknowledgement file communicates that some records within a file are processed successfully 
and some have errors, only the records with errors should be in the corrected version of the file. Including 
records that had no errors or had warnings results in duplicate records in the system. 
The Acknowledgment Files section is updated with: 
1. Clearer information on how to read the acknowledgement file to understand whether your files were 
processed. 
2. Instructions for how to create a new file with just the fixed records when an error is reported in the 
acknowledgement file. 
3. Clear guidance that records that did not receive an error should not be included in the corrected file. 
4. Updated examples of acknowledgement files to show: 
a. Successful validation for all records 
b. File level error 
c. Employer level error and warning 
Clarification of revisioning files 
Duplicate files are detected by file name. As such it is important to use the revisioning indicator that is built 
into the file naming convention when updates are necessary for a file. More information is now provided for 
when you should revision a file and example file names are provided. 
Update to return CSV file size maximum specifications 
Previously the maximum file size was less than 5MB. The new maximum files size for CSV files is both less 
than 5MB and fewer than 5,000 return records.

CT Paid Leave file naming convention 
Each file submitted to the CT Paid Leave Authority is expected to adhere to the following naming pattern. 
The pattern consists of a series of informational nodes, with each node separated by an underscore. The 
nodes enable understanding the expected file contents immediately, and the consistency of node 
sequences allow the files to stay organized within a normal folder structure. Additionally, automated 
processes depend on the file names, so an inconsistent named file will not be processed.

Revisioning File Names 
Each file uploaded to the SFTP server must have a unique file name following the CT Paid Leave naming 
convention to be processed. When an error is reported in an acknowledgement file, a revision of the file 
must be made. To properly name the revised file, increase the two-character revision indicator, found after 
the third underscore, as shown in the example below. 
• Original File Name:  CTPL_ RTN_426092234_00_20210112152238.xml 
• First Revision File Name: CTPL_ RTN_426092234_01_20210112152238.xml 
• Second Revision File Name: CTPL_ RTN_426092234_02_20210112152238.xml 
Important 
Use the two-character revision indicator for every new version of a file uploaded, to resolve errors identified 
in the acknowledgement file.

Enrollment file specifications 
Enrollment files are only necessary for third-party administrators (TPAs) using batch processing. They 
provide key information to CT Paid Leave about which client employers a TPA will be remitting on behalf of. 
• File Size: Enrollment files must be less than 5 MB. 
• Batches of Files: If you have a large volume of files, upload them onto the SFTP server in smaller 
batches and wait until they complete processing before uploading your next batch of files. 
• Employer nodes will repeat for each employer included in the enrollment file 
• For active relationships, no ending date (RelEndDate) should be supplied. 
• Following upload and processing of the enrollment file, an acknowledgement file will be placed in 
your outbound SFTP folder verifying the success of the submission, or in the case of an unsuccessful 
submission, error reasons will be provided. 
While the preferred format for enrollment files is XML, an alternate CSV format can be used by TPAs who 
are unable to produce XML. See section CSV Format: Enrollment File for more information.

CSV Format: Enrollment File 
File Layout 
Adhere to the following when creating CSV files: 
1. The enrollment file must contain a header record with each named field separated from the next by a 
comma. 
2. Strings containing commas must be enclosed in double quotes. All other strings may optionally be 
enclosed in double quotes. 
3. For each record in the file, the first nine fields must be the same (TPA information in orange 
background). 
4. The record count will equal to the number of Client Employers. 
5. EmplyrRelEndDate will only have a value when ending a relationship with the specified Employer. 
The record layout below is shown vertically rather than horizontally for ease of readability.

Return file specifications 
CT Paid Leave accepts batch return files in two file formats: XML or CSV. Both file formats contain the same 
information. 
• File Size:  
o All Return file formats must be less than 5 MB. 
o CSV files must contain fewer than 5,000 return records. 
• Batches of Files: If you have a large volume of files, upload them onto the SFTP server in smaller 
batches and wait until they complete processing before uploading your next batch of files. 
• Numeric amount fields on the return file do not contain commas between hundreds and thousands. 
The acceptable format is 999999.99 or similar. The format 999,999.99 will result in your return not 
being processed. 
• Each return must be attributed to a quarter and should not span multiple quarters. 
Important 
Do not include employee level records in return and amended return files. 
In 2024, CT Paid Leave made inclusion of the employee data optional (it had previously been required). 
Effective July 2025, if employee data is in a return or amended return file, the file is not processed, and an 
error is reported in the acknowledgement file.

Employer Element 
• The <tns:Employer></tns:Employer> element will contain information that identifies the records 
reported to have warnings or errors. 
• If no warning or error is encountered for any employer, the employer element will be empty and 
represented as a self-closing element that looks like <tns:Employer/> 
• Information provided in the Employer Element when a warning or error is encountered is: 
o Employer FEIN – Employer Federal Identification Number value listed in the uploaded file 
o Employer Business Name – Employer Business Name as listed in the uploaded file 
o Status – Indicates whether the employer record processed 
 Valid – Indicates the record processed 
 Invalid – Indicates the record did not process 
Error Element 
• The <tns:Error></tns:Error> element is nested within the Employer Element. It provides  more 
information about the reported warning or error. 
o Error Number – Eight-digit number that is assigned to an error. Error and warning codes which 
can be referenced in section Return Error & Warning Codes. 
o Error Text – Description of the error or warning 
o Error Level – Indicates whether the issue identified is an error or a warning 
 Valid – Indicates the record processed 
 Invalid – Indicates the record did not process 
ErrorLevel Element 
• The <tns:ErrorLevel></tns:ErrorLevel> element is nested within the Error Element. The ErrorLevel 
element content will inform you whether it is an error or warning that is being reported. The action 
you must take is different for each. 
o E = Error, the record was not accepted due to the error listed. Create and submit a new file for 
just the corrected employer records. 
o W = Warning, the record was accepted, but the warning will give you information to resolve to 
prevent this issue on future files. Do not correct and resubmit, this information is only to 
assist you with correcting future files.

the outbound folder with the file extension .error appended to the file name. Create a new file with only the

Automated Clearing House (ACH) credit entries must be delivered to the Bank of America (BofA) in the

The CT Paid Leave Authority requires the NACHA Header Record 5, Detail Record 6 and Addendum Record 7 
to be formatted according to the file specifications in this section. 
Read the field level instructions carefully. Some values in the records will be fixed and are supplied in the 
“Contents” column of the record layout, while others will vary by submission. 
Important 
Adhering to the file specifications is necessary for CT Paid Leave contributions to process successfully. 
Incorrectly formatted contributions will be returned. 
Penny Tests

contribution, following these steps: 
• Format NACHA file according to the specifications provided in the following sections: 
o CCD file specification for third-party administrators 
 NACHA RECORD 5 – Batch Header Record Layout Format 
 NACHA RECORD 6 – Entry Detail Record Layout Format

 NACHA RECORD 5 – Batch Header Record Layout Format

• Include the Authority’s banking information in the file, which is:  
o Bank of America Bank Transit Number: 011900254 
o The Authority Bank Account Number: 00000385015954138 
• Indicate a penny deposit to the Authority account. 
• Follow your normal process for submitting the NACHA file to your banking institution. 
• To request a refund from your penny test, submit contact us inquiry. Select "Help with Contribution 
Payments/Reporting" as the contact reason. In the body of your inquiry, specify the date you 
submitted your penny test. 
• The Authority will respond to your inquiry through email with confirmation that the penny test was 
successful or help with how to resolve the issue that prevented the penny from being processed. 
• The Authority will issue a refund of the penny test back to the issuing bank account within thirty 
days.
