## Resposta

**CodProfesion must be sent as a 7-digit code: take the 4-digit CNO code from the Data Dictionary and pad it on the right with zeros up to 7 digits.**

| DD value (CNO, table T90) | XML `CodProfesion` |
|---|---|
| `3123` | `3123000` |

Sending the bare 4-digit code (`3123`) is rejected by Certific@2. This was the defect corrected in **SEPE CERTIFICA Spec v1.1** (HRBS-13757, ~4 September 2026), with the T90 CNO table (seg-social.es) as the source.

Three implementation points:

- **The Data Dictionary does not change.** It keeps storing the 4-digit CNO (T90). The padding is a transformation in the report mapping, applied only when the XML is built.
- **Pad on the right, not the left.** `0003123` is wrong; the zeros go after the code.
- **Status:** the corrected v1.1 mapping has not yet been confirmed as accepted on the Certific@2 portal (HRBS-13757 is still pending on the reporter). Treat a first successful live submission as the confirmation.
