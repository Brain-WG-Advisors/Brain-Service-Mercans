|  | THREE OUTBOUND INTEGRATIONS, ONE MESSAGE — AND WHY THAT IS NOT A SHORTCUT | BE-SIR-001 registers three separate outbound integrations that all use pain.001.001.09: OUT-09 the net pay file, OUT-10 the payment of social security contributions, and OUT-11 the payment of the wage withholding tax. They are NOT three file layouts. They are the same message with a different creditor, a different category purpose and a different structured communication, and the SIR itself records the distinction in exactly those terms — OUT-09 carries product mapping 'true' because it is built from the net pay line, while OUT-10 and OUT-11 carry 'false' because each is a single instructed amount with a structured communication. Specifying them once, with the three variants set out in the File Structure and Field Options sheets, is what the source supports. Producing three near-identical workbooks would create three documents that drift apart against one Febelfin guideline. |  |  |  |
|  | THE AMOUNT FORMAT IS THE OPPOSITE OF EVERY OTHER BELGIAN FILE IN THIS SET | The DmfA, the Finprof 274 return and the Belcotax 281.10 all express amounts as INTEGERS IN EUROCENT with no decimal separator: EUR 2,003.47 is written 200347. ISO 20022 does not. Here the amount is a DECIMAL WITH A POINT and an explicit currency attribute: <InstdAmt Ccy="EUR">2003.47</InstdAmt>. An engine that applies one convention across all Belgian outbound files will be wrong by a factor of one hundred in one direction or the other. |  |  |  |
|  | NOT A STATUTORY REPORT — AND SPECIFIED ANYWAY, DELIBERATELY | Strictly this is a payment instruction to a commercial bank, not a filing with an authority, and no Belgian authority authenticates or validates it. It is specified here because BE-SIR-001 registers it as a mandatory outbound integration, because CCG Module 10.2 records that wages must be paid by transfer, because an official field-level source exists and is held, and because CCG Module 1.2 attaches a Belgian statutory rule to one of its fields — the preceding-banking-day rule on the execution date. Omitting it would leave that rule with no specification. |  |  |  |
|  | WHAT FEBELFIN DOES NOT STANDARDISE | BE-SIR-001 Section 3.3 puts it precisely: there is NO Belgian authority that authenticates a payment file, and this is a confirmed absence rather than a gap. Authentication is set by the client's bank and its channel — a banking portal, Isabel 6, EBICS, or a host-to-host link — and differs per bank. Gap G25 extends the same point to cutoff times, file size and transaction limits, the reject code subset and the retry policy. Febelfin standardises the MESSAGE, not the CHANNEL. Column T carries that caveat on every row because it applies to every row. |  |  |  |
