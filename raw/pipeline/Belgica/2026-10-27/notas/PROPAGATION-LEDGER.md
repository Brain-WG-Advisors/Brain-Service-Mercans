## 0. The load-bearing caveat — read before using this file

**Every entry in §1 to §1H was assembled without a register, and it has to say so. The register
now exists — that does not retroactively make those entries complete.**

Section P5 of the auditor doctrine turns propagation from a guess into a checklist by reading the
`consumed_by` column of `00-official-sources/legal-basis-register.csv`. ~~**Belgium has no such
register** (limitation L-01).~~ **BELGIUM NOW HAS ONE.** It was built on **18 August 2026** under
`L-01` (§1I): **63 rows, the pipeline's own 20-column contract, `consumed_by` populated on 61 of
them and MEASURED rather than asserted** — every row carries regex probes run against a plain-text
dump of all eight delivered artifacts, so the column records where a figure demonstrably appears,
not where somebody expected it to.

~~Every edge below was reconstructed by hand from artifact text, which means **I can only record
edges I happened to read.**~~ **Every edge in §1 through §1H was reconstructed by hand from artifact
text**, which means **those sections record only the edges somebody happened to read.** An edge that
sat in a cell nobody had grepped is not in them, and its absence there is still not evidence that it
does not exist.

**What the register changes, and what it deliberately does not.**

- **Forward, from 18 August 2026:** `legal-basis-register.csv` **is** the propagation checklist. When
  a figure moves, read its row's `consumed_by`, open every artifact unit that column names, and write
  one ledger line per consumer with a verdict. That is §4's standing rule with the guesswork taken
  out: the question *"who else consumes this?"* now has a file that answers it instead of a sweep that
  approximates it. A missing consumer line is from now on a **defect**, not a limitation.
- **Backward, for §1 to §1H:** those sections **stay exactly as written and are NOT reissued against
  the register.** They remain **historically accurate for what was actually checked at the time** —
  each line names the file that was re-opened and carries `RESOLVED` or `CARRIED` with the id that
  owns it. Rewriting them against a source they did not have would turn an honest record of a hand
  sweep into a false claim of a systematic one, which is the F29 shape §4 warns about.
- **The two are therefore not the same kind of record, and the boundary is dated at §1I.** Auditing
  coverage of anything before 18 August 2026, the struck-through caveat above still governs. Auditing
  anything after it, expect a `consumed_by` lookup.
- **The register is not a completeness claim either.** It is a **retrofit of the load-bearing
  figures**, not an inventory of every number in a 3 MB corpus — 63 rows against a corpus with
  thousands of values. A figure with no register row is exactly as unchecked as it was on 17 August;
  §3.6 stays open for that residue and now says so in those terms.

The register does not make this file complete. It makes the *next* line in it cheap and checkable —
which is precisely what §1B.5 measured the absent column as costing.

**Retroactive entries.** This ledger did not exist while the fixes of 15–17 August were being
applied, so §1 reconstructs those edges after the fact from the artifacts on disk and their
changelogs. Reconstruction is weaker than same-day recording, and every §1 line was verified
against the artifact rather than against the log that claimed it. Two of them turned out to be false
claims (rows 1.4 and 1.9) — which is exactly why the rule is *check the artifact, not the log*.

**One line in this file per change, the same day, every time — and the line must name the file the
