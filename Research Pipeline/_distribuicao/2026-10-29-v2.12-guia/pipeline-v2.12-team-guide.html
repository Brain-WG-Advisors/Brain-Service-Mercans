Mercans compliance · Research pipeline v2.12

Which part of the pipeline do I need?

Version 2.12 arrives in three parts that look like one. Each serves a different job. Pick yours below and follow only that path.

Ask or review in claude.ai Nothing to install

The three skills are now published to the Mercans organisation. They give the chat the method; they do not build a country.

  1. Check the skills are on

    In claude.ai or Claude Desktop go to Customize → Skills and switch on mercans-pipeline-methodology, mercans-compliance-workflow and mercans-artifact-toolkit.

  2. Remove old copies

    If you uploaded these skills yourself before, switch your copies off so only the organisation version is active.

  3. Turn on code execution

    Settings → Capabilities. The toolkit uses it to inspect and validate xlsx and docx files you upload.

  4. Test it

    Ask in a new chat:

    What does Stage 9 do in pipeline v2.12, and when may a check be skipped?

    A correct answer says that missing country support is a FAIL unless an exemption is recorded.

Build a country in Git Bash Same as before

The script runs in Git Bash and calls Claude Code in the background, stage by stage. It does not need the plugin.

Research→CCG, specs, DD, WTC, SIR, payslip→Stage 9 audit (blocks)→QA and country skill→Design→Release (Stage 13)

You need: Claude Code logged in with your Claude account, Git Bash, Python 3 with openpyxl python-docx jsonschema, and no ANTHROPIC_API_KEY set.

  1. Unzip the package

    Use a short path such as C:\mercans\v2.12. Do not unzip the skill zips inside chat/.

  2. Copy the pipeline folder

    If you already have ~/mercans-pipeline from v2.9, rename it first.

    mv ~/mercans-pipeline ~/mercans-pipeline-v2.9 # only if it exists cp -r /c/mercans/v2.12/code/mercans-pipeline/pipeline ~/mercans-pipeline cd ~/mercans-pipeline
  3. Dry run (builds nothing)
    GENERATE_PROMPTS_ONLY=true bash mercans_pipeline_v2_12.sh "Country" CC CUR 2026 English

    Look for Claude CLI: ok and All v2.4 reference files present. Then delete the test CC-compliance/ folder.

  4. Real run
    CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000 nohup bash mercans_pipeline_v2_12.sh "Country" CC CUR 2026 English > CC-v212.log 2>&1 &

    Resume from a stage with START_STAGE=N. Keep the laptop plugged in and awake: sleep kills the run without an error.

Build with agents in Claude Code Optional

The plugin does the same job as the script, but as a team of four agents you can follow and steer inside a Claude Code session. Each one hands its work to the next through files.

Scaffolder · scope and folders→Source hunter · law from official sources→Builder · writes the artifacts→QA auditor · rejects or passes
  1. Install the plugin

    In Claude Code, from the unzipped package:

    /plugin marketplace add C:/mercans/v2.12/code /plugin install mercans-pipeline@mercans-compliance

    Restart Claude Code and check with /plugin and /agents.

  2. Start a build

    Ask Claude Code to run the country-build skill for your country. It calls the four agents in order and stops at each review gate.

Use either the script or the agents for a country, not both.

What changed in v2.12

We checked the France build against the official engine and validator. The 63 errors that were ours became new checks, so the next country cannot repeat them.

Nothing is skipped silently

If a check cannot run because the country lacks support, Stage 9 now fails. To pass, record an exemption with a reason, an official source link and a date.

One source for every value

Every rate or ceiling carries a tag like [[FACT:key=value]]. Fix it once and every artifact follows.

Ten new blocking checks

For example: a code the WTC does not have, a tax flag with no legal basis, a payslip missing a statutory line or whose net does not add up, a repealed article.

Errors caught

Of the 63 France errors, v2.11 fully caught 5. v2.12 fully catches 18 and partly catches 38 more.

“It stopped” — is that normal?

The banner says v2.8

NormalOld label inside the script. The file you run is v2.12.

Dry run ends with STAGE 13 HALTED (C43)

NormalThe dry run builds nothing, so the release stage has nothing to release.

Stage 9 FAIL on C34, C35, C36, C48, C50, C57 or C71

ExpectedThe country has no support for that check. Add validation_exemptions.<check> (reason, official source URL, decided_on) to _pipeline/build-manifest.json. See CHANGELOG-v2.12.md §1.

ANTHROPIC_API_KEY is set

Run unset ANTHROPIC_API_KEY and remove it from your environment variables. The script uses your Claude account, not an API key.

claude CLI not found / test failed

Install Claude Code, open a new Git Bash and run claude once to log in.

Required v2.4 reference file missing

The pipeline folder was not copied whole. Repeat the copy step.

Anything else: send Wallisson the last 30 lines of the log. Full detail is in START-HERE.md, INSTALL.md and CHANGELOG-v2.12.md inside the package.
