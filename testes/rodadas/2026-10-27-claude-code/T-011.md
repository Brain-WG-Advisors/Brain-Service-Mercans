# T-011

**Pergunta:** Ukraine, Unified ESV/PIT Report (J05 package, D1 annex), XML header (DECLARHEAD): how should the fields C_REG, C_RAJ and C_STI_ORIG be populated?

**Resposta:**
They are not fixed values. They identify the territorial DPS (State Tax Service) body to which each legal entity submits the report:
- C_REG = region (oblast) code of that receiving DPS body;
- C_RAJ = district code of that receiving DPS body;
- C_STI_ORIG = code of the receiving DPS body, taken from the DPS directory SPR_STI.XML, and always equal to C_REG × 100 + C_RAJ.

The values "26 / 50 / 2650" in the earlier D1 spec (v3, 21/08, "confirmed fixed in tested template") are only the Kyiv body (ГУ ДПС у м. Києві) of the test template and must not be hard-coded. They are populated per legal entity from the DD fields `dps_region_code`, `dps_district_code` and `dps_tax_authority_code` (DD V4.1+, Country Fields rows 83–85, Legal Entity HR). All three are mandatory in the XSD. Do not confuse them with KATOTTG, the employee's "Oblast (Region)", or the Derzhstat C_REG/C_RAJ (SPR_SSCU) used in 1-PV.
