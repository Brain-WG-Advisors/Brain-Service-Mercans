Report Matrix!A22	DETAILED COMPLIANCE NOTES (Colombia-specific)
Report Matrix!A23	SUBMISSION CHANNEL
Report Matrix!A24	- Channel: upload of the two fixed-width files (or keying) on the web site of a licensed information operator chosen by the payer. Source: AT3 v15 ch. 1 s.0, p. 7.
Report Matrix!A25	- The planilla is self-settled and paid electronically: pension payers with 20 or more pensioners have been bound to the electronic modality since 6 March 2017 (Decreto 780 de 2016 art. 3.2.3.9).
Report Matrix!A26	- Prerequisite: the payer must appear in the Ministry of Health file 'INFORMACIÓN PAGADORES DE PENSIONES', placed monthly on each operator's secure FTP; a payer that does not appear requests inclusion from the Subdirección de Pensiones y Otras Prestaciones (AT3 v15 §2.1.2.2, p. 16).
Report Matrix!A27	- The payer updates its File Type 1 registration with the operator in July and January, as a precondition for settling the planilla of that month (AT3 v15 §1.1, pp. 11-12).
Report Matrix!A28	SCOPE OF THIS REPORT
Report Matrix!A29	- Covers the pensions the employer pays directly as pension payer type 01, pensioner types 5 and 6, and the pensioner type 9 records of their additional UPC beneficiaries (AT3 v15 ch. 4 §1 table 3, pp. 100-101).
Report Matrix!A30	- Active employees, including employed pensioners in active service, are reported in the employees' PILA under Anexo Técnico 2 (CO-PILA-003), a different file with a different layout.
Report Matrix!A31	- Payments that are not a pension (for example an instalment of a retirement bonus) have no record here: every detail record carries a pension type (campo 9) and a mesada (campo 58).
Report Matrix!A32	CONTRIBUTIONS SETTLED
Report Matrix!A33	- Health: borne in full by the pensioner (Ley 100 de 1993 art. 143) on the mesada capped at 25 SMLMV; rate by total mesada and contribution period, from January 2024 4% (1 SMLMV) / 10% (more than 1 and up to 3 SMLMV) / 12% (more than 3 SMLMV), earlier periods as in T2R2-048 (Ley 100 de 1993 art. 204 par. 5; Res. MSPS 1271 de 2023 art. 1).
Report Matrix!A34	- Fondo de Solidaridad Pensional, subsistence subaccount: 1% for a total mesada above 10 and up to 20 SMLMV, 2% above 20 SMLMV, on the mesada (AT3 v15 §2.2.2.2 and §2.2.2.21; Ley 797 de 2003 art. 8).
Report Matrix!A35	- Pension: only for pension types that contribute (11 and 14 'para compartir', 4; optional 12, 20, 21) per R6 (AT3 v15 ch. 4 §6 table 9, pp. 107-108); R6 also marks 7 and 22, which are not valid for payer type 01 (R02, AT3 v15 pp. 102-103).
Report Matrix!A36	- Family compensation fund: optional for every pension type (R6, 'O').
Report Matrix!A37	- No occupational risk, SENA or ICBF in this file.
Report Matrix!A38	RELATED FILINGS / CROSS-REFERENCES
Report Matrix!A39	- The pensions paid by the employer and the deductions withheld from them are also reported in the electronic payroll (CO-DIAN-001): Res. DIAN 000227 de 2025 art. 1.5.3.2.3 includes 'pagos a los pensionados a cargo del empleador'.
Report Matrix!A40	- Totals records types 3 to 7 (pension, FSP subsistence, health, CCF and total payable) and the output files to the administradoras are generated by the information operator, not by the payer (AT3 v15 ch. 2-3, pp. 65-98).

File Structure!A2	═══ SUBMISSION FORMAT ═══
File Structure!A3	Governing layout
File Structure!B3	Res. MSPS 2388 de 2016, Anexo Técnico 3 'Aportes a Seguridad Social de Pensionados', version 15 dated 24-07-2026 (cited as AT3 v15), incorporating up to Res. MSPS 1529 de 2026.
File Structure!A4	Channel
File Structure!B4	Upload of the two fixed-width flat files into the web portal of a licensed information operator, or keying on the same portal. The pension payer never transacts directly with the government for these contributions.
File Structure!A5	Electronic modality
File Structure!B5	Pension payers with 20 or more pensioners self-settle and pay through the electronic planilla (Decreto 780 de 2016 art. 3.2.3.9).
File Structure!A6	Payer listing
File Structure!B6	Planilla types P, R, L and V require the payer to appear in the Ministry file 'INFORMACIÓN PAGADORES DE PENSIONES' (AT3 v15 §2.1.2.2, pp. 16-20).
File Structure!A7	Operator upload wrapper
File Structure!B7	The two files below follow the official annex position by position. Each operador's upload wrapper and any additional validations it applies are published by the operador and held in the information-operator configuration for the operador the payer has chosen.
File Structure!A8	═══ FILE FORMAT ═══
File Structure!A9	File type
File Structure!B9	Two fixed-width flat text files, one record per line: File Type 1 'Datos generales del pagador de pensiones' and File Type 2 'Información planilla integrada' (AT3 v15 ch. 1 s.0, p. 7).
File Structure!A10	Numeric fields (tipo N)
File Structure!B10	Right-justified, ZERO-filled to the left (AT3 v15 ch. 1 s.0, p. 7; §2, p. 13).
File Structure!A11	Alphanumeric fields (tipo A)
File Structure!B11	Left-justified, SPACE-filled to the right (AT3 v15 ch. 1 s.0, p. 7; §2, p. 13).
File Structure!A12	Record lengths
File Structure!B12	File Type 1 = 482 positions. File Type 2 Record Type 1 = 285 positions. File Type 2 Record Type 2 = 519 positions. All three equal the printed totals of AT3 v15 (pp. 11, 16, 39).
File Structure!A13	Rounding
File Structure!B13	The contribution base (IBC, campo 39) is rounded UP to the whole peso and each contribution value is rounded UP to the next multiple of 100 (Decreto 780 de 2016 art. 3.2.1.5, text of Decreto 1990 de 2016 art. 1). AT3 v15 requires the rounding rules in force in campos 41, 42, 45, 46, 47, 49 and 52 (pp. 53, 59-63).
File Structure!A14	Rate fields
File Structure!B14	Campos 40, 48 and 51 are numeric, seven positions. AT3 v15 prints the decimal layout for campo 51: decimal, left-justified, zeros to the right, 2.0% = 0.02000 (p. 63). The layout of every rate field is held in the file-format configuration as published by the chosen information operator.
File Structure!A15	Registration update
File Structure!B15	The pension payer updates its File Type 1 data with the information operator in July and January, before settling the planilla of that month; the operator notifies a payer that has not updated at least two months in advance (AT3 v15 pp. 11-12).

Population Rules!A1	POPULATION RULES - HOW TO FILL EACH FIELD FROM PAYROLL
Population Rules!A2	Field Name
Population Rules!B2	Source System

Population Rules!D2	Edge Cases
Population Rules!A3	═══ WHO IS REPORTED ═══
Population Rules!A4	Population of Record Type 2
Population Rules!B4	Payroll engine
Population Rules!C4	One detail record per pensioner whose pension the employer pays directly (pension WT 62154) and per pension type held, for every month the pension is in force, plus one pensioner type 9 record per additional UPC beneficiary. The employer files as pension payer type 01; the pensioner type is 5 (mesada capped at 25 SMMLV) or 6 (no cap) (AT3 v15 §2.2, p. 21; ch. 4 §1, pp. 99-101).
Population Rules!D4	Employees, including employed pensioners in active service, go in CO-PILA-003. Instalments of a retirement bonus are not a pension and have no record. A suspended mesada is still reported, with SUS = S.
Population Rules!A5	Payer listing prerequisite
Population Rules!B5	Configuration
Population Rules!C5	Before the first planilla P, R, L or V, the payer must appear in the Ministry file 'INFORMACIÓN PAGADORES DE PENSIONES' (monthly, operator FTP). Where it does not, it requests inclusion from the Subdirección de Pensiones y Otras Prestaciones of the Ministry of Health (AT3 v15 §2.1.2.2, pp. 16-20).
Population Rules!D5	The listing is held by the Ministry and the operator; the engine records the payer's listing status as configuration and does not produce the planilla without it.
Population Rules!A6	═══ MANDATORY FIELD RULES ═══
Population Rules!A7	Mesada and total mesada (T2R2-058, T2R2-063)
Population Rules!B7	Payroll engine
Population Rules!C7	Campo 58 = the mesada of the month (WT 62154), uncapped. Campo 63 = the total mesada: equal to campo 58 for a pension that is not shared (types 10 and 13 included); the sum of the shared amounts, of the Colombian and foreign mesadas, or of all survivor beneficiaries otherwise (AT3 v15 §2.2.2.27-28, p. 64).
Population Rules!D7	Campo 63 drives the health band and the FSP factor; campo 58 is the base of the FSP and CCF amounts. Keep the two separate even where they are equal.
Population Rules!A8	Contribution base (T2R2-039)
Population Rules!B8	Payroll engine
Population Rules!C8	IBC = mesada, capped at 25 SMLMV, rounded UP to the whole peso (AT3 v15 §2.2.2.13, p. 52; Decreto 780 de 2016 arts. 2.2.1.1.2.1 and 3.2.1.5).
Population Rules!D8	Minimum 1 SMLMV for pension types 10 and 13 (AT3 v15 ch. 4 §7, pp. 108-109). Zero with SUS = S and for pensioner type 9.
Population Rules!A9	Health rate and contribution (T2R2-048, T2R2-049)
Population Rules!B9	Payroll engine
Population Rules!C9	Select the rate on campo 63 for the contribution period: from January 2024 a mesada of 1 SMLMV 4%; more than 1 and up to 3 SMLMV 10%; more than 3 SMLMV 12% (Ley 100 de 1993 art. 204 par. 5 with Ley 2294 de 2023 art. 78; Res. MSPS 1271 de 2023 art. 1); periods 2020-2023 as in T2R2-048. Campo 49 = campo 48 x campo 39, rounded UP to the next multiple of 100. The amount is the sum of the health WTs 21645 / 21646 / 21647 withheld from the mesada.
Population Rules!D9	Pensioner abroad (campo 18 = X): rate 0% and contribution zero. With fewer than 30 days (ING / RET), the operator checks campo 63 against the proportion of the SMLMV for the days reported (AT3 v15 p. 64).
Population Rules!A10	Fondo de Solidaridad Pensional (T2R2-036, T2R2-047)
Population Rules!B10	Payroll engine
Population Rules!C10	Where campo 63 exceeds 10 SMLMV: campo 47 = campo 58 x 1% (more than 10 and up to 20 SMLMV) or x 2% (more than 20 SMLMV), rounded UP to the next multiple of 100; campo 36 = days (30 for a full month). The amount is the sum of the FSP WTs 21643 / 21648 / 21644 (AT3 v15 §2.2.2.21, pp. 61-62; Ley 797 de 2003 art. 8).
Population Rules!D10	Several pensions of one beneficiary in the same planilla: the factor follows the sum of campo 63 and applies to each campo 58. Campos 45 and 46 stay zero for pension types 10 and 13; the operator liquidates them only for the contributing types.
Population Rules!A11	Days (T2R2-035 to T2R2-038)
Population Rules!B11	Payroll engine
Population Rules!C11	30 for a full month whatever its calendar length; fewer only with ING or RET. Health days mandatory; pension days only for the contributing pension types; FSP days where the mesada exceeds 10 SMLMV; CCF days where a CCF is reported (AT3 v15 §2.2.2.10-12, pp. 51-52).
Population Rules!D11	Health days zero only with campo 18 = X; 30 for a pensioner type 9 record.
Population Rules!A12	═══ CRITICAL VALIDATION RULES ═══
Population Rules!A13	Header-to-detail consistency
Population Rules!B13	Engine (validation)
Population Rules!C13	T2R1-003 to T2R1-009 equal File Type 1 campos 1, 2, 3, 4, 10, 5 and 6; T2R1-016 equals A1-027; T2R1-017 equals A1-025. T2R1-014 = number of pensioners in Record Type 2 excluding pensioner type 9; T2R1-015 = sum of campo 58 excluding pensioner type 9 (AT3 v15 §2.1.1, pp. 14-15).
Population Rules!D13	The type 9 exclusion applies to both the count and the payroll total.
Population Rules!A14	Coherence tables R01 to R6
Population Rules!B14	Engine (validation)
Population Rules!C14	Before submission check: pensioner type against payer type 01 (5, 6, 9); pension type against payer type 01 (2, 3, 4, 8, 10, 11, 12, 13, 14, 20, 21); pension type against pensioner type (R03); planilla type against pensioner type (R04); change events against pension type (table 8); subsystems against pension type (R6) (AT3 v15 ch. 4 §1-6, pp. 99-108).
Population Rules!D14	A combination outside these tables makes the operator reject the whole planilla.
Population Rules!A15	Payer and pensioner identities differ
Population Rules!B15	Engine (validation)
Population Rules!C15	The pensioner's document type and number must differ from the payer's (AT3 v15 p. 39).
Population Rules!D15	The exception for pension type 16 (foreign pensioners under international agreements) does not arise for payer type 01.
Population Rules!A16	Change event to date interlock
Population Rules!B16	Engine (validation)
Population Rules!C16	ING with campo 55, RET with campo 56, VSP with campo 57, SUS with campos 60-61; each date must fall within the period settled. TDE, TAE, TDP, TAP and campos 31 and 33 are always blank (AT3 v15 §2.2.1, pp. 29-39).
Population Rules!D16	VSP and SUS are not reported together.
Population Rules!A17	═══ AMOUNT FORMAT RULES ═══
Population Rules!A18	Rounding is UP
Population Rules!B18	Engine (formatting)
Population Rules!C18	IBC rounded UP to the whole peso; each contribution (campos 41, 42, 45, 46, 47, 49, 52) rounded UP to the next multiple of 100 (Decreto 780 de 2016 art. 3.2.1.5, text of Decreto 1990 de 2016 art. 1).
Population Rules!D18	Reconcile with payroll on unrounded values with a tolerance of 100 pesos per contribution.
Population Rules!A19	Numeric and alphanumeric justification
Population Rules!B19	Engine (formatting)
Population Rules!C19	Numeric fields right-justified and zero-filled; alphanumeric fields left-justified and space-filled (AT3 v15 ch. 1 s.0, p. 7).
Population Rules!D19	An empty numeric field is a run of zeros, an empty alphanumeric field a run of spaces.
