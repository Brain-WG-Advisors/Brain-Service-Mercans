## Resposta

**Host:** the DPAE goes to URSSAF's own deposit point, not to net-entreprises. In API mode the payroll software deposits on **`https://depot.dpae-edi.urssaf.fr`** with `POST /deposer-dsn/1.0/`. The resource really is named `/deposer-dsn/`, even for the DPAE; URSSAF's guide says so explicitly, so don't "correct" it to `/deposer-dpae/`.

The full API flow (REST over HTTPS, régime général only) uses four hosts:

| Step | URL |
|---|---|
| Authentication | `POST https://mon.urssaf.fr/authentifier_dpae` |
| Deposit | `POST https://depot.dpae-edi.urssaf.fr/deposer-dsn/1.0/` |
| List returns | `GET https://consultation.dpae-edi.urssaf.fr/lister-retours-flux/1.0/{idFlux}` |
| Download a return | `GET https://telechargement.dpae-edi.urssaf.fr/telecharger-retour/1.0/{idFlux}/{idRetour}` |

If the software acts as a **concentrateur**, the deposit, consultation and download calls must use **port 8443**. Authentication stays on 443. A wrong port returns a 403 that looks like an entitlement problem. There is no test environment. Tests run on production with a test indicator in the payload.

**Accepted formats:** two, both valid on the API:

1. **Format 120 flat file (TXT).** Each record is 990 bytes: 989 characters plus an `LF` terminator, not CRLF. Fields are left-aligned and blank-padded, mandatory fields must be uppercase, and the encoding is ISO-8859-1. `C_VERSION` is `120` for a real filing and `TST` for a test. Versions 100 and 110 are rejected.
2. **`FR_DUE_Upload` XML**, encoded in ISO-8859-1. The test indicator is `FR_DUE_Upload.Test.Indicator`.

Both are sent with `Content-Type: text/plain` and `Content-Encoding: gzip`. Zip, tar and other archives are **not** accepted on the API. Archive handling exists only for upload through the portal. One deposit can hold many hires, up to 100 MB.

**Which one to build:** the artifact recommends **format 120 flat**. URSSAF publishes its full record layout and writes its control tables and error codes against it. For the XML, there is no public XSD (`DUE_Upload.xsd`) and only one example instance. The two formats also use **different value domains**: format 120 uses numeric `C_TYPE_CONTRAT` = `1`/`2`/`3`, while XML uses mnemonic `CDI`. So they can't be treated as two serialisations of one model.

**Points to carry**

- **Correction to older material:** `scope_manifest.json` recorded the DPAE as "via net-entreprises.fr, XML". The runbook corrects this. NetDPAE on net-entreprises is a **manual portal alternative**, not the API path. The old channels are closed: email to `embauche@due.fr` ended 1 July 2022, and CFT ended end-2022.
- **`[VERIFY WITH RA]`:** the API value of `C_APPLICATION` (positions 15–18 of format 120) is not stated in any source. It is `"DUE "` on the email channel and `"CFT"` on CFT. The same goes for the `C_URSSAF` code table (Annexe II.1) and the XSD. All three should be requested at enrolment from `api-dpae@acoss.fr`, because the API has restricted access with no self-service subscription.
- **Returns:** returns 10 (AEE) and 11 (conformity certificate or anomaly report) come in DSN format. Returns 41 (AR) and 20 (BIS) come in DPAE-specific formats. Only a populated `R_DOSSIER` in return 41 proves the DPAE was registered. An HTTP 200 on deposit only means the pre-controls passed.
- **Legal basis:** electronic filing is mandatory for employers that filed more than 50 DPAE in the previous calendar year (Code du travail D.1221-18). Breaching that obligation costs 0.5 % of the monthly social security ceiling per employee (D.1221-19). The DPAE can be filed at the earliest 8 days before the hire (R.1221-4) and must be filed before work begins (L.1221-10). It cannot be filed late.
- **Planned change:** the DPAE is expected to become DSN event signal type 10, but not before 1 January 2027. In 2026 it remains a separate channel and must not be routed through the API DSN.
