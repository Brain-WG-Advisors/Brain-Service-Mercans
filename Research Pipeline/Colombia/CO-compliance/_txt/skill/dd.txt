R12|  | Version | Effective Date | Change Description | Status | Updated By
R13|  | 1 | 2026-09-04 | Initial version - Colombia Data Dictionary (private-sector master data), fiscal year 2026. Field set classified from the six in-scope report specifications in 04-reports-spec (CO-DIAN-001 nomina electronica, CO-DIAN-002 Formulario 350, CO-PILA-003, CO-DIAN-004 Formulario 220, CO-DIAN-005 Formato 2276, CO-CESANTIAS-006) by System Mapping, in lock-step with the spec col-E 'Payroll Field (Y/N)' flag (build_co_specs._DD_MASTER_MAPPINGS), and extended with the calculation-driving master-data groups of CCG Module 2.2 that do not surface on a filing (working time, withholding procedure, pension regime, concurrent employer, non-salary pact, work modality). ONE DELIBERATE DEVIATION from col-E lock-step: Contract.Contractual_Salary is flagged Payroll Field = Y in the specs but is an AMOUNT and is therefore excluded from the DD and routed to the Wage Type Catalogue, per the CLAUDE.md scope rule. Option mappers apply the private-sector filter: civil servants, military and police, independent workers and service contractors, domestic workers, community mothers, associated-work cooperative members and the self-insured are excluded, and the excluded codes are named in each mapper's Notes column so they are rejected at validation. Codes, lengths and masks are taken from the published Resolucion DIAN 000013 de 2021 Anexo Tecnico, Resolucion MSPS 2388 de 2016 Anexo Tecnico 2, Resolucion DIAN 000227 de 2025 and the published severance-deposit layouts; DERIVED items are flagged for RA confirmation in the Additional Notes. | Released | Mercans Compliance
R14|  | 1.1 | 2026-09-07 | DD<->SPEC ALIGNMENT PATCH (mandatory pre-audit step), reconciling this Data Dictionary with the six Specs in 04-reports-spec. CROSS-REFERENCES: 49 field rows carried a stale or incomplete 'Spec ref' citation - a systematic off-by-N drift across the NIE, A1 and T2R blocks (for example Hire Date cited NIE057, which does not exist; the anexo field is NIE002 FechaIngreso, and the whole PILA employer block A1-011 to A1-017 was displaced by one). Every citation is now re-derived from the System Mapping join and states the artefact, the field ID and the Mandatory flag for each Spec that carries the field. OPTION MAPPERS: Worker Type code 40 (beneficiario de UPC adicional) REMOVED - it is absent from DIAN Anexo Tecnico table 5.5.3 and is a health-coverage beneficiary rather than an employee, so it could never be a valid NIE041 value; Employee Document Type code 47 abbreviation corrected to PEP, verbatim from Anexo table 5.2.1; the Worker Sub-Type hard rule aligned to the PILA statutory list (1, 2, 3, 4, 5, 6, 9, 12) with the in-scope subset named separately and the code-width trap recorded. NEW MAPPER 'Employee Document Type (PILA / Cesantias)' carrying the eight two-letter values of PILA Anexo Tecnico 2 campo 3 (CC, CE, TI, PA, CD, SC, RC, PE) plus the cesantias-only PT - this closes the contradiction in which CD and SC were named as valid in the numeric mapper's constraints but had no row, and gives PILA T2R2-003, T2R2-074 and CO-CESANTIAS-006 T03 a complete code table. Contract.Contractual_Salary remains OUT of the Data Dictionary as an amount; the deviation is now resolved at source, the spec build having been corrected to flag it Payroll Field = N, so this is no longer a deviation. OPTION-MAPPER ASSIGNMENT (CHECK 1): 'Principal Contributor Document Type' (CO-PILA-003 T2R2-074) was pointed at the mapper 'Employer Document Type', contradicting its own Pre-Defined Format and notes, which both say it takes the PILA two-letter CONTRIBUTOR catalogue. The two lists differ in exactly two places - the employer list carries NI and lacks RC - so the wrong mapper admitted a corporate NIT as a principal contributor's document type and rejected a registro civil, which is precisely the beneficiary case the field exists for. The field now references 'Employee Document Type (PILA / Cesantias)', matching Spec T2R2-074, which points at the same Sheet 6 table as T2R2-003; the employer mapper's own note, which had claimed T2R2-074 as a second referrer, is corrected. This also resolves the orphan-mapper finding for the contributor catalogue added earlier in this patch. CODE-PREFIX PATTERNS (CHECK 6): the seven administradora fields (employer ARL, employee ARL, EPS and EPS transfer, AFP and AFP transfer, CCF) stated only 'A(6) - administradoras catalogue' in Pre-Defined Format while the Specs stated the full six-position prefix pattern; the pattern ^(ARL\|EPS\|EOC\|AFP\|CCF\|FSP)[0-9]{3}$ is now carried on both sides so the two documents describe the same format. The severance-savings fund code is deliberately left at N(2), being a different published catalogue. Full record: 07-qa-crosscheck/CO-ALIGNMENT-PATCH.md. | Released | Mercans Compliance

=== SHEET: Instructions (dims A1:Z995, max_row 995, max_col 26) ===

~
R2|  | Instructions
~
R4|  | Field Name | Instructions/Descriptions
R5|  | Field Group | Mercans' field group name. The values in this field should not be updated.
R6|  | Field Name | Data field name in Mercans' system. This field should be updated only for the field in the Implementation-Specific Fields tab. The values in this field are not always the same as the actual database field names.
R7|  | Internal Code | Mercans' data field code. This field is used to map Client's data against Mercans fields.
R8|  | Label in Local Language | Field name in the local language and should reflect the same terminology as used on statutory forms or local language reports.
R9|  | Field Description (Long Description of the Field) | Include a full description of the respective data field.
R10|  | Data Type - Mandatory (M), Conditional Mandatory (CM), Optional (O) | The values of this field should not be updated for Universal or Country-Specific Fields. Each Implementation-Specific Fields must be categorized as a either Mandatory, Conditional Mandatory or Optional fields. Mandatory fields must be filled for each employee record and Conditional Mandatory fields only if a certain condition is met.
R11|  | Pre-Condition for Conditional Mandatory | This field should be filled for all data fields identified as Conditional-Minatory. It should include the condition that makes the respective field mandatory.
R12|  | Field Type (Text, Number, Date, Integer, Decimal, Counter) | Available field type options are Text, Number, Date, Integer, Decimal, and Counter. Each field must include a field type.
R13|  | Pre-Defined Format | Field format should be provided for the fields that must be in specific formats; i.e. (999) 123-4567, etc.
R14|  | Validations, Restrictions, Pick Lists etc. | Field-specific validations are defined in this field. Validations can include specific pick lists, length validations, etc.
R15|  | Default Value | A default value should be filled for each record if no other value is applicable.
